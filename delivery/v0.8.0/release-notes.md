## GoalAnchor v0.8.0

v0.8.0 新增严格工作流，帮助工程任务从已确认的目标和计划，经过证据审核、授权执行，最终按原验收条件关闭。

### 新增

- **版本化目标与证据快照**：目标和计划带有明确版本；审核可使用冻结的证据内容、SHA-256 摘要、来源和有效期。摘要只绑定已采集内容，不单独证明来源真实。
- **有限的多 Agent 审核**：同轮 Reviewer 使用相同目标、提示和材料；Arbiter 汇总结论，Meta Reviewer 以独立角色复核。重要发现需要记录处置依据；争议最多复审两轮，仍未解决时停止并等待用户决策。
- **持久化的一次性授权**：普通执行中，一份授权只允许一次初次派发。SQLite 账本记录授权、消费、撤销、过期和执行回执；受限恢复须取得新的明确许可，见下项。
- **结构化问题与回答**：问题记录关联目标/计划版本和阻塞工作项；授权类问题绑定精确操作。相同操作可复用既有问题，方向回答不会自动授予执行权限。问题没有独立的“触发原因”字段；授权提示展示精确操作信息。
- **谨慎处理未知结果**：外部操作可能已执行但结果不明时，系统不会自动重发。`resume_transport` 仅在取得新的签名用户许可、原授权和原操作仍有效，且原操作中冻结的 backend/key 与许可及证明完全匹配，并有当前有效的独立签名幂等测试证据时，才允许同一 attempt 额外传输一次；传输确认不会清除原 `UNKNOWN`，仍须由可信 observer 提交关联证据并通过 `reconcile` 确认结果。
- **受条件约束的观察复用**：`reuse_observation` 仅在原验收条件完全相同、当前对象摘要与原观察来源链匹配，并提供当前可信 observer 签署的无影响证明时复用结果；不恢复旧授权。
- **宿主绑定**：工作流记录受信控制侧提供的宿主版本、模型、运行模式和 Hook 信息。相关信息变化后，原策略绑定失效，需显式重新验证。
- **审核材料投递**：`review_packets` 将完整材料关联到审核角色、会话及投递回执。回执仅证明材料已送达，不证明模型已阅读、理解或独立判断。
- **工作流 CLI**：`python -m goalanchor workflow` 提供 `demo`、`capabilities`、只读 `status` / `audit`，以及显式执行的 `recover`。`demo` 使用合成审核和测试批准，仅演示本地接入流程。

### 修复

- 根据 Reviewer 和 Arbiter 的实际结论识别分歧，避免仅依赖“无分歧”的自报标志。
- 关闭目标前校验验收条件是否仍与当前基线一致，避免用替换、缺失或新增的条件关闭原目标。
- 在派发和关闭前重新核对授权、证据、取消状态和有效期，避免旧状态继续触发操作或错误关闭目标。

### 兼容性与宿主边界

- 旧辅助 API 保留 PASS 空证据的兼容行为；严格工作流要求绑定实际证据内容。
- 缺少可信来源证明的旧授权会以 `LEGACY_UNVERIFIED` 拒绝使用；不做通用自动迁移。
- Codex App Server 为 `LIMITED`，仅支持明确声明的命令回调；Skill/MCP-only 接入为 `ADVISORY`；没有可用原生接口的宿主为 `UNAVAILABLE`。这些能力等级不代表所有工具入口均受拦截。
- 事件签名只证明配置的受信控制侧发出了该事件，不证明真人亲自点击授权。工作目录检查不构成 shell 沙箱；部署方仍须保护签名密钥、账本、observer 和 executor。
